# 🔋 Power Monitor

Автоматичний моніторинг наявності електроенергії вдома зі сповіщеннями в Telegram.

## 💖 Підтримка

Якщо проєкт корисний для вас не забудьте поставити ⭐️ та [підтримати донатом](https://send.monobank.ua/jar/3QTpZrNn2T).

## 📋 Опис

Проєкт перевіряє доступність домашнього пристрою (роутера, сервера, камери) за IP та портом. Якщо пристрій перестав відповідати, світло зникло. Якщо знову відповідає, світло з'явилося. При зміні стану бот відправляє повідомлення в Telegram з часом події та тривалістю попереднього стану. Перевірка запускається через GitHub Actions за зовнішнім тригером.

## ✨ Можливості

- 🔌 Перевірка наявності світла через TCP-з'єднання з домашнім пристроєм.
- 📱 Надсилання сповіщень в Telegram при зникненні та появі світла.
- ⏱️ Відображення часу події та тривалості відключення або роботи.
- 🛡️ Захист від хибних спрацювань: зміна стану підтверджується повторною перевіркою через 3 хвилини.
- 🔄 Автоматичний запуск через GitHub Actions.

## 🚀 Швидкий старт

### 1. Форк репозиторію

Натисніть кнопку "Fork" у правому верхньому куті сторінки репозиторію.

### 2. Підготовка домашнього пристрою

Потрібен пристрій, який живиться від мережі та доступний з інтернету за IP і портом. Найпростіший варіант: роутер з увімкненим доступом до веб-інтерфейсу з інтернету або прокинутим портом на будь-який домашній пристрій.

1. Дізнайтесь вашу публічну IP-адресу, наприклад на [ifconfig.me](https://ifconfig.me). Якщо IP динамічний, налаштуйте DDNS на роутері та використовуйте отримане доменне ім'я замість IP.
2. У налаштуваннях роутера відкрийте порт назовні (Port Forwarding або Remote Management).
3. Перевірте з мобільного інтернету, що порт відповідає, наприклад командою `nc -zv <IP> <PORT>`.

### 3. Створення Telegram бота

1. Відкрийте [@BotFather](https://t.me/BotFather) в Telegram.
2. Відправте команду `/newbot`.
3. Вкажіть ім'я та username для бота.
4. Збережіть отриманий токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### 4. Отримання Chat ID

1. Відправте будь-яке повідомлення вашому боту.
2. Відкрийте в браузері `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`.
3. Знайдіть значення у форматі `"chat":{"id":123456789}` — це ваш Chat ID.

### 5. Налаштування Secrets

Перейдіть в **Settings** → **Secrets and variables** → **Actions** вашого форкнутого репозиторію та додайте наступні secrets:

| Secret               | Опис                                | Приклад                                   |
| -------------------- | ----------------------------------- | ----------------------------------------- |
| `IP`                 | Публічний IP або DDNS-ім'я пристрою | `93.72.10.15` або `home.example.ddns.net` |
| `PORT`               | Відкритий порт на пристрої          | `8080`                                    |
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather            | `123456789:ABCdefGHI...`                  |
| `TELEGRAM_CHAT_ID`   | ID чату в Telegram                  | `123456789` або `-123456789` (для каналу) |
| `PAT`                | Personal Access Token для GitHub    | [Інструкція](#створення-pat)              |

#### Створення PAT

1. Перейдіть в **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
2. Натисніть **Generate new token**.
3. Підтвердіть доступ одним із запропонованих методів, наприклад `Use GitHub Mobile`.
4. Вкажіть назву токена, наприклад `power-monitor`.
5. Встановіть термін дії (або `No expiration` на свій розсуд).
6. Оберіть **Repository access** → `Only select repositories` та оберіть клонований репозиторій.
7. Натисніть **+ Add permissions** → відмітьте `Read access to metadata` та `Read and Write access to code`.
8. Натисніть **Generate token** та скопіюйте токен.

### 6. Налаштування зовнішнього тригера

Вбудований cron у GitHub Actions не використовується, бо він спрацьовує з великими затримками. Замість цього перевірку запускає зовнішній сервіс через GitHub API. Підійде будь-який cron-сервіс, наприклад [cron-job.org](https://cron-job.org).

Створіть завдання з такими параметрами:

- **URL**: `https://api.github.com/repos/YOUR_USERNAME/power-monitor/dispatches`
- **Метод**: `POST`
- **Інтервал**: кожні 5–10 хвилин ([детальніше](#частота-перевірки))
- **Заголовки**:
  - `Accept: application/vnd.github+json`
  - `Authorization: Bearer <PAT>`
  - `Content-Type: application/json`
- **Тіло запиту**: `{"event_type": "check-power"}`

Для тригера можна використати той самий PAT, що й у secrets.

### 7. Запуск Actions

1. Перейдіть на вкладку **Actions**.
2. Знайдіть та відкрийте workflow з назвою **"Power monitor"**.
3. Праворуч вгорі натисніть **Run workflow** → і ще раз на **Run workflow** всередині випадного меню.

Перший запуск завжди відправить повідомлення з поточним станом, бо попередній стан невідомий.

## 🛠 Локальний запуск

### Вимоги

- Node.js (версія вказана в `.nvmrc`)
- npm

### Встановлення

```bash
# Клонування репозиторію
git clone https://github.com/YOUR_USERNAME/power-monitor.git
cd power-monitor

# Встановлення залежностей
npm install
```

### Налаштування

Створіть файл `.env` в кореневій директорії (скористуйтесь `.env.example`) з вмістом такого штибу:

```env
IP=93.72.10.15
PORT=8080
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-12346789
```

### Запуск

```bash
# Збірка та разовий запуск
npm run dev

# Тільки збірка
npm run build

# Тільки запуск зібраного коду
npm run start
```

## 🔍 Як це працює

1. **Перевірка пристрою**: Скрипт відкриває TCP-з'єднання до вказаного IP та порту з таймаутом 5 секунд. Успішне з'єднання означає, що світло є.
2. **Порівняння зі станом**: Результат порівнюється з попереднім станом із файлу `artifacts/status.json`. Якщо стан не змінився, скрипт завершується.
3. **Підтвердження зміни**: Якщо стан змінився, скрипт чекає 3 хвилини та перевіряє ще раз. Це відсікає короткі збої мережі та перезавантаження роутера.
4. **Відправлення повідомлення**: Після підтвердження формується повідомлення з часом події та тривалістю попереднього стану і відправляється в Telegram.
5. **Збереження стану**: Новий стан зберігається у файл та комітиться в репозиторій як артефакт. Щоб не засмічувати історію, коміт зі станом кожного разу оновлюється замість створення нового.

## ⚙️ Налаштування

### Частота перевірки

Інтервал задається у зовнішньому cron-сервісі. Рекомендовано кожні 5–10 хвилин.

Запускати частіше, ніж раз на 5 хвилин, не варто: при зміні стану один запуск триває близько 4 хвилин через очікування підтвердження. Запуски, що накладаються, стають у чергу завдяки `concurrency` у workflow, тож дублікатів повідомлень не буде, але й користі від частіших перевірок теж.

Затримка сповіщення в найгіршому випадку дорівнює інтервалу плюс 3–4 хвилини.

### Таймаути

Відредагуйте значення у файлі `src/constants.ts`:

```ts
export const REQUEST_TIMEOUT = 5 * 1_000 // таймаут TCP-з'єднання
export const RETRY_TIMEOUT = 3 * 60 * 1_000 // очікування перед підтвердженням
```

### Моніторинг декількох адрес

Для моніторингу декількох пристроїв створіть окремі репозиторії або дублюйте workflow з різними secrets.

## ⚠️ Обмеження

- Скрипт не відрізняє відсутність світла від відсутності інтернету. Якщо провайдер ліг, а світло є, надійде повідомлення про відключення.
- Після появи світла роутеру потрібна 1–2 хвилини, щоб завантажитись і підключитись до мережі. Час у повідомленні відображає момент, коли пристрій знову став доступний.
- Відключення коротші за інтервал перевірки можуть не потрапити в моніторинг.
- Кожен запуск тарифікується GitHub як мінімум 1 хвилина Actions. Для приватного репозиторію з інтервалом 5 хвилин безкоштовної квоти не вистачить, для публічного хвилини не рахуються.
