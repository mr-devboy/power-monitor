# 🔋 Power Monitor

Автоматичний моніторинг наявності електроенергії вдома зі сповіщеннями в Telegram.

## 💖 Підтримка

Якщо проєкт корисний для тебе, не забудь поставити ⭐️ та [підтримати донатом](https://send.monobank.ua/jar/3QTpZrNn2T).

## 📋 Опис

Проєкт перевіряє доступність домашнього пристрою (роутера, сервера, камери) за IP та портом. Якщо пристрій перестав відповідати, світло зникло. Якщо знову відповідає, світло з'явилося. При зміні стану бот надсилає повідомлення в Telegram з часом події та тривалістю попереднього стану. Перевірка запускається через GitHub Actions за зовнішнім тригером.

## ✨ Можливості

- 🔌 Перевірка наявності світла через TCP-з'єднання з домашнім пристроєм.
- 📱 Надсилання сповіщень в Telegram при зникненні та появі світла.
- ⏱️ Відображення часу події та тривалості відключення або роботи.
- ⚡️ Перевірка кожні 30 секунд: про появу світла бот повідомляє приблизно за 1–2 хвилини.
- 🛡️ Захист від хибних спрацювань: поява світла підтверджується протягом 1 хвилини, зникнення — протягом 3 хвилин.
- 🔄 Автоматичний запуск через GitHub Actions.
- 🗂 Зберігання стану бота в окремій гілці `artifacts`, щоб у `main` був лише код.

## 🚀 Швидкий старт

### 1. Форк репозиторію

Натисни кнопку "Fork" у правому верхньому куті сторінки репозиторію.

### 2. Підготовка домашнього пристрою

Потрібен пристрій, який живиться від мережі та доступний з інтернету за IP і портом. Найпростіший варіант: роутер з увімкненим доступом до веб-інтерфейсу з інтернету або прокинутим портом на будь-який домашній пристрій.

1. Дізнайся свою публічну IP-адресу, наприклад на [ifconfig.me](https://ifconfig.me). Якщо IP динамічний, налаштуй DDNS на роутері та використовуй отримане доменне ім'я замість IP.
2. У налаштуваннях роутера відкрий порт назовні (Port Forwarding або Remote Management).
3. Перевір з мобільного інтернету, що порт відповідає, наприклад командою `nc -zv <IP> <PORT>`.

### 3. Створення Telegram бота

1. Відкрий [@BotFather](https://t.me/BotFather) в Telegram.
2. Відправ команду `/newbot`.
3. Вкажи ім'я та username для бота.
4. Збережи отриманий токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### 4. Отримання Chat ID

1. Відправ будь-яке повідомлення своєму боту.
2. Відкрий у браузері `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`.
3. Знайди значення у форматі `"chat":{"id":123456789}` — це твій Chat ID.

### 5. Налаштування Secrets

Перейди в **Settings** → **Secrets and variables** → **Actions** свого форкнутого репозиторію та додай такі secrets:

| Secret               | Опис                                | Приклад                                   |
| -------------------- | ----------------------------------- | ----------------------------------------- |
| `IP`                 | Публічний IP або DDNS-ім'я пристрою | `93.72.10.15` або `home.example.ddns.net` |
| `PORT`               | Відкритий порт на пристрої          | `8080`                                    |
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather            | `123456789:ABCdefGHI...`                  |
| `TELEGRAM_CHAT_ID`   | ID чату в Telegram                  | `123456789` або `-123456789` (для каналу) |

### 6. Налаштування зовнішнього тригера

Вбудований cron у GitHub Actions не використовується, бо він спрацьовує з великими затримками. Замість цього перевірку запускає зовнішній cron-сервіс через GitHub API, наприклад [cron-job.org](https://cron-job.org). Для цього йому потрібен Personal Access Token (PAT).

#### Створення PAT

1. Перейди в **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
2. Натисни **Generate new token**.
3. Підтверди доступ одним із запропонованих методів, наприклад `Use GitHub Mobile`.
4. Вкажи назву токена, наприклад `power-monitor`.
5. Встанови термін дії (або `No expiration` на свій розсуд).
6. Обери **Repository access** → `Only select repositories` та обери свій форкнутий репозиторій.
7. Натисни **+ Add permissions** → обери `Contents` і встанови доступ `Read and write`. `Metadata` з доступом `Read` додасться автоматично.
8. Натисни **Generate token** та скопіюй токен.

#### Створення завдання в cron-сервісі

Створи завдання з такими параметрами:

- **URL**: `https://api.github.com/repos/YOUR_USERNAME/power-monitor/dispatches`
- **Метод**: `POST`
- **Інтервал**: кожні 5 хвилин ([детальніше](#зміна-частоти-перевірки))
- **Заголовки**:
  - `Accept: application/vnd.github+json`
  - `Authorization: Bearer <PAT>`
  - `Content-Type: application/json`
- **Тіло запиту**: `{"event_type": "check-power"}`

### 7. Запуск Actions

1. Перейди на вкладку **Actions**.
2. Знайди та відкрий workflow з назвою **"Power monitor"**.
3. Праворуч вгорі натисни **Run workflow** → і ще раз на **Run workflow** всередині випадного меню.

Перший запуск завжди надсилає повідомлення з поточним станом, бо попередній стан невідомий.

## 🛠 Локальний запуск

### Вимоги

- Node.js (версія вказана в `.nvmrc`)
- npm

### Встановлення

```bash
# Клонування репозиторію
git clone https://github.com/YOUR_USERNAME/power-monitor.git
cd power-monitor

# Встановлення залежностей
npm install
```

### Налаштування

Створи файл `.env` в кореневій директорії (скористайся `.env.example`) з таким вмістом:

```env
IP=93.72.10.15
PORT=8080
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-12346789
```

### Запуск

```bash
# Збірка та разовий запуск
npm run dev

# Тільки збірка
npm run build

# Тільки запуск зібраного коду
npm run start
```

## 🔍 Як це працює

1. **Перевірка пристрою**: Протягом 3 хвилин скрипт кожні 30 секунд відкриває TCP-з'єднання до вказаного IP та порту з таймаутом 5 секунд. Успішне з'єднання означає, що світло є.
2. **Порівняння зі станом**: Результат порівнюється з попереднім станом із файлу `status.json` у гілці `artifacts`. Якщо стан не змінився, скрипт чекає наступної перевірки.
3. **Підтвердження зміни**: Якщо стан змінився, скрипт і далі перевіряє його кожні 30 секунд: появу світла протягом 1 хвилини, зникнення протягом 3 хвилин. Якщо хоч одна перевірка показала попередній стан, зміна ігнорується. Це відсікає короткі збої мережі та блимання світла. Розпочате підтвердження завершується, навіть якщо 3 хвилини запуску вже минули.
4. **Відправлення повідомлення**: Після підтвердження формується повідомлення з часом, коли зміну помітили вперше, та тривалістю попереднього стану і відправляється в Telegram.
5. **Збереження стану**: Новий стан зберігається у файлі `status.json` в окремій гілці `artifacts`. Workflow підключає цю гілку як папку `artifacts/` і після роботи скрипта комітить зміни назад. У новому форку гілка створюється автоматично під час першого запуску. При локальному запуску стан зберігається в папці `artifacts/`, яка не потрапляє до репозиторію.

### Коли світло з'явилося:

## ⚙️ Налаштування

### Зміна частоти перевірки

Інтервал задається у зовнішньому cron-сервісі. Рекомендовано кожні 5 хвилин: разом з підготовкою один запуск триває близько 4 хвилин, тож перевірки йдуть майже без перерв.

Якщо змінюєш інтервал, зміни й `CHECK_DURATION` у `src/constants.ts`: він має бути приблизно на 2 хвилини меншим за інтервал. Запуски, що накладаються, стають у чергу завдяки `concurrency` у workflow, тож дублікатів повідомлень не буде.

Про появу світла бот повідомляє в середньому за 1–2 хвилини, про зникнення — за 3–4 хвилини.

### Таймаути

Відредагуй значення у файлі `src/constants.ts`:

```ts
export const REQUEST_TIMEOUT = 5 * 1_000 // таймаут TCP-з'єднання
export const CHECK_INTERVAL = 30 * 1_000 // пауза між перевірками
export const CHECK_DURATION = 3 * 60 * 1_000 // скільки триває один запуск
export const ONLINE_CONFIRM_TIMEOUT = 1 * 60 * 1_000 // підтвердження появи світла
export const OFFLINE_CONFIRM_TIMEOUT = 3 * 60 * 1_000 // підтвердження зникнення світла
```

## ⚠️ Обмеження

- Скрипт не відрізняє відсутність світла від відсутності інтернету. Якщо провайдер ліг, а світло є, надійде повідомлення про відключення.
- Після появи світла роутеру потрібна 1–2 хвилини, щоб завантажитись і підключитись до мережі. Час у повідомленні відображає момент, коли пристрій знову став доступний.
- Відключення, коротші за інтервал перевірки, можуть не потрапити в моніторинг.
- Кожен запуск триває близько 4 хвилин Actions. Для приватного репозиторію з інтервалом 5 хвилин безкоштовної квоти не вистачить, для публічного хвилини не рахуються.
